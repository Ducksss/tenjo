Win → collect → reset

Fresh proof from the winning identity → one pickup → next entry starts with one chance.

Production pickup is gated pending liveness validation. A win resets losses even without pickup.

Lose → one more chance

Next drop in the same series uses one extra chance, capped at six. A different series has its own counter.

On-chain loser deposits refund in settlement. A pending entry that missed the chain is not a loss.

    Build and operations

    Current

    GitHub source → Next build → Vercel. Explicit hosted SQL migrations. No durable job worker is present. Draw and registration retries are request-triggered.

    Added in this review

    Pull request/main CI: npm ci → typecheck → lint → unit/service tests → build. Browser tests remain a local verification command. Move/testnet evidence is separate.

    What to discuss next

    Implemented

    Make the current product clearer

    • Put browseable drops below the introduction.
    • Show the featured deposit instead of a blanket free-entry claim.
    • Separate saved, registered and excluded entries.
    • Add regression coverage and application CI.
    Before an on-chain pilot

    Make recovery dependable

    • Durable registration queue with deadline monitoring.
    • Reconcile chain commits after database failure.
    • Retain paid transaction digests and retry confirmation only.
    • Record real World and Sui evidence.
    Product decisions

    Make returning easier

    • Downloadable receipt; opt-in local history.
    • Explain public code/wallet linkability before entry.
    • Define missed-entry, cancellation and unclaimed-seat policy.
    • Choose credential eligibility and production pickup assurance.
    Pilot readiness

    Measure what is actually live

    • Configured ≠ reachable ≠ end-to-end verified.
    • Show per-drop server/chain authority.
    • Protect expensive routes and add safe operational alerts.
    • Use the actual 300-entrant limit; validate judge access to the private repository.
